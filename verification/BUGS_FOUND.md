# SentinelFlow Bugs & Integration Deficiencies

### Bug B-001: Complete Frontend-Backend Disconnection
- **Test**: `TC-UI-01` / Full System Integration
- **Observed Behavior**: The Frontend UI operates 100% on inline static mocks and `setTimeout` promises (`frontend/src/api/incidents.ts`, `frontend/src/api/response.ts`). It makes zero network HTTP calls to the Python backend or AWS Lambda handlers.
- **Expected Behavior**: Frontend should dispatch HTTP REST requests to fetch live incident data, attack graph nodes, AI analysis narratives, and submit remediation authorization requests to the backend.
- **Affected File/Endpoint**: `frontend/src/api/*`, `frontend/src/components/*`
- **Severity**: Critical

### Bug B-002: Incomplete Route Handling for Non-Existent or Secondary Incidents
- **Test**: `TC-UI-02` / `PHASE 8 — FAILURE TESTING`
- **Observed Behavior**: Navigating to `/incidents/DOES-NOT-EXIST` or `/incidents/INC-046` renders a hardcoded fallback string `"Insufficient Data for {id}"` rather than triggering a proper 404 or backend search request.
- **Expected Behavior**: App should return a proper 404/Not Found state or query the backend API for incident details.
- **Affected File/Endpoint**: `frontend/src/routes/IncidentDetail.tsx`
- **Severity**: High

### Bug B-003: Static AI Analyst Panel Without Interactive Input Capability
- **Test**: `TC-UI-03` / `PHASE 5 — AI GROUNDING`
- **Observed Behavior**: `AIAnalystPanel.tsx` and `routes/AIAnalyst.tsx` display hardcoded narrative text for query `"Why is this incident classified as high risk?"`. There is no input textarea or form submit capability to ask custom questions (such as `"What is the weather in Kolkata?"`).
- **Expected Behavior**: Interactive query input allowing SOC analysts to prompt the AI Investigator.
- **Affected File/Endpoint**: `frontend/src/components/ai/AIAnalystPanel.tsx`
- **Severity**: Medium

### Bug B-004: Hardcoded Audit Log UI Disconnected from Backend Store
- **Test**: `TC-UI-04` / `PHASE 7 — AUDIT LOG`
- **Observed Behavior**: `AuditLog.tsx` renders a hardcoded static array (`AL-9001` through `AL-9005`) that is completely isolated from the backend's `AppendOnlyAuditStore` (`backend/src/audit_store.py`). Approving an action in the UI does not append an entry to the Audit Log view.
- **Expected Behavior**: Audit Log UI should display real-time immutable audit records generated by the backend authorizer and pipeline.
- **Affected File/Endpoint**: `frontend/src/routes/AuditLog.tsx`, `frontend/src/context/ResponseContext.tsx`
- **Severity**: Medium
