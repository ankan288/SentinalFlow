# SentinelFlow Bugs & Architectural Deficiencies

### Bug B-001: Complete Frontend-Backend UI Disconnection
- **Test Phase**: Phase 0 / Phase 1 / Full System Integration
- **Observed Behavior**: The Frontend UI operates 100% on inline static mock state (`isDemoMode: true`, `frontend/src/components/attack-graph/AttackGraphCanvas.tsx`, `frontend/src/routes/AuditLog.tsx`). It makes zero HTTP REST requests to the Python backend pipeline or AWS Lambda handlers.
- **Expected Behavior**: Frontend should dispatch HTTP REST requests to fetch live incident data, attack graph nodes, AI analysis narratives, and submit remediation requests to backend.
- **Affected Files**: `frontend/src/components/*`, `frontend/src/routes/*`
- **Severity**: Critical
- **Suggested Fix**: Update `Incidents.tsx`, `IncidentDetail.tsx`, `AttackGraphCanvas.tsx`, and `AuditLog.tsx` to invoke `incidentsService` and `apiClient` endpoints when `isDemoMode` is false.

---

### Bug B-002: Incomplete Route Handling for Non-Existent Incidents
- **Test Phase**: Phase 9 Failure Testing
- **Observed Behavior**: Navigating to `/incidents/DOES-NOT-EXIST` renders a hardcoded fallback string `"Insufficient Data for {id}"` rather than triggering a proper 404 Not Found state.
- **Expected Behavior**: App should return a 404 state or query the backend API.
- **Affected File**: `frontend/src/routes/IncidentDetail.tsx`
- **Severity**: High
- **Suggested Fix**: Add 404 error boundary and API fetch failure handling in `IncidentDetail.tsx`.

---

### Bug B-003: Static AI Analyst Panel Without Interactive Prompt Input
- **Test Phase**: Phase 6 AI Grounding
- **Observed Behavior**: `AIAnalystPanel.tsx` displays hardcoded narrative text. There is no prompt input textarea to submit custom queries to the AI Investigator.
- **Expected Behavior**: Interactive query input form for SOC analysts.
- **Affected File**: `frontend/src/components/ai/AIAnalystPanel.tsx`
- **Severity**: Medium
- **Suggested Fix**: Add a text input form dispatching prompts to `/incidents/{id}/analyze`.

---

### Bug B-004: Hardcoded Audit Log UI Disconnected from Backend Store
- **Test Phase**: Phase 8 Audit Logging
- **Observed Behavior**: `AuditLog.tsx` renders a static hardcoded array (`AL-9001` through `AL-9005`) that is isolated from the backend's `AppendOnlyAuditStore`.
- **Expected Behavior**: Audit Log UI should fetch live immutable audit records generated by the Cedar authorizer.
- **Affected File**: `frontend/src/routes/AuditLog.tsx`
- **Severity**: Medium
- **Suggested Fix**: Wire `AuditLog.tsx` to fetch records from backend audit API.
